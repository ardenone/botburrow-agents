# ArgoCD ApplicationSet Sync Analysis for botburrow-agents

**Date:** 2026-02-08 09:42 UTC
**Bead:** bd-3kh (Fix ArgoCD ApplicationSet sync for botburrow-agents deployment)
**Related:** bd-1v9 (original), bd-cni (workaround)

## Summary

The ArgoCD ApplicationSet `manifest-appset-apexalgo-iad` is not deploying resources for the `botburrow-agents` namespace. The namespace exists with ArgoCD tracking annotations but contains zero resources.

## Investigation Findings

### 1. Namespace Status

```bash
kubectl get namespace botburrow-agents -o yaml
```

- Namespace **exists** with ArgoCD tracking-id annotation: `botburrow-agents-ns-apexalgo-iad`
- Created: `2026-02-01T19:46:37Z` (7 days ago)
- ResourceVersion: `477894869`
- **No resources deployed** in the namespace

### 2. ApplicationSet Configuration

**Location:** `ardenone-cluster/cluster-configuration/apexalgo-iad/apexalgo-iad-applicationset.yml`

**Generator:**
```yaml
generators:
  - git:
      repoURL: https://github.com/ardenone/ardenone-cluster
      revision: HEAD
      directories:
        - path: cluster-configuration/apexalgo-iad/*
```

**Exclude Pattern:** `{ignore/*,*application.yml}`

**Application Naming:** `{{path.basename}}-ns-apexalgo-iad` → `botburrow-agents-ns-apexalgo-iad`

### 3. Root Cause Analysis

#### Previous Issues Identified and Fixed

1. **`botburrow-agents-application.yml` was being excluded**
   - The file ended with `application.yml`
   - ApplicationSet exclude pattern `*application.yml` prevented discovery
   - **Fixed:** Removed `botburrow-agents-application.yml` (commit e0fe28189)

2. **No kustomization.yaml (potential issue)**
   - Added `kustomization.yaml` to enable proper ArgoCD sync
   - References all individual YAML manifests
   - **Fixed:** Added `kustomization.yaml` (commit f66d708d9)

#### Current Status

Both fixes have been pushed to GitHub:
- Commit e0fe28189: "fix(bd-3kh): Remove botburrow-agents-application.yml..."
- Commit f66d708d9: "feat(bd-3kh): Add kustomization.yaml to fix ArgoCD..."

**However, resources are still not deployed** as of 2026-02-08 09:42 UTC (10+ minutes after fixes pushed).

### 4. Comparison with Working Deployments

**Forgejo (working):**
- Namespace: `forgejo` with tracking-id `forgejo-ns-apexalgo-iad`
- Resources deployed: Deployment, Service, Pods
- No `kustomization.yaml` file
- Directory structure similar to botburrow-agents

**Key Differences:**
- None significant in directory structure
- Both have similar manifest files (namespace.yml, deployment.yaml, etc.)
- Neither has kustomization (until botburrow-agents got one)

### 5. Possible Explanations

Since the namespace exists but resources aren't syncing:

1. **Application exists but is in a failed state**
   - Possible sync errors (can't verify due to RBAC)
   - Health check failures blocking sync

2. **Application not being generated by ApplicationSet**
   - Directory discovery issue (unlikely since namespace exists)
   - Git sync delay (unlikely after 10+ minutes)

3. **ApplicationSet has an issue**
   - Generator problems
   - Template rendering issues for botburrow-agents specifically

4. **Resource-specific issues**
   - Validation errors in manifests
   - Dependency failures
   - Permission issues

### 6. RBAC Blocking Direct Access

Cannot verify ArgoCD Application status due to RBAC:

```bash
curl -s --header "Authorization: Bearer $(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
  "https://kubernetes.default.svc.cluster.local/apis/argoproj.io/v1alpha1/namespaces/argocd/applications"
```

Returns: `403 Forbidden - User "system:serviceaccount:devpod:default" cannot list resource "applications"`

Also blocked via apexalgo-iad proxy:
```bash
curl http://kubectl-apexalgo-iad.devpod.svc.cluster.local:8001/apis/argoproj.io/v1alpha1/namespaces/argocd/applications
```

Returns: `403 Forbidden - User "system:serviceaccount:devpod-observer:devpod-observer" cannot list resource "applications"`

  project: default
  source:
    repoURL: https://github.com/ardenone/ardenone-cluster
    targetRevision: HEAD
    path: cluster-configuration/apexalgo-iad/botburrow-agents
  destination:
    server: https://hcp-99476ebb-4133-4a21-ac6a-6e2bdf6794c0.spot.rackspace.com

  syncPolicy:
    automated:
      prune: true
      selfHeal: true
      allowEmpty: true
    syncOptions:
      - CreateNamespace=true
EOF
